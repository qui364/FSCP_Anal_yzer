# AGENTS.md

Инструкции для агентов (Claude Code, Codex и др.). Проект — статичный просмотрщик конфигурации ГК в формате `.fscp` и журналов CSV. Сборки, тестов и линтеров нет.

Структура формата и справочники — в `docs/`: `FSCP.md` (формат, XML, журнал, источники), `DRIVERS.md`, `DEVICE-DEFAULTS.md`, `PARAM-ENUMS.md`, `EVENTS.md`. Здесь — только устройство просмотрщика и правила работы.

## Правила работы

- Образцы — данные реальной установки: не копировать в логи, документацию, коммиты и сторонние сервисы; в `AGENTS.md` и `docs/` — только структура формата и справочники, без имён, дат, объёмов и значений конкретной установки.
- Архив распаковывать в отдельную пустую папку вне репозитория, ничего из распакованного не запускать.
- XML огромные (десятки МБ): читать частями (поиск, `Select-Xml`, потоковый разбор).
- Изменили поведение — обновите этот файл и `docs/`, если это затрагивает формат или справочники.

## Структура

- `src/` — просмотрщик без бэкенда и сборки: `index.html` (разметка), `style.css`, `js/`, `icons/`, `vendor/` (Vue 3.5.13 `vue.global.prod.js`, JSZip 3.10.1 `jszip.min.js`), `data/`.
- `src/data/` — справочники-скрипты (глобальные константы): `drivers.js` (`DRIVERS`), `events.js` (`EVENTS`, `EVENT_DESCS`), `device-defaults.js` (`DEVICE_DEFAULTS`), `param-enums.js` (`PARAM_ENUMS`), `plan-icons.js` (`PLAN_ICONS`), `tree-icons.js` (`TREE_ICONS`), `du-config.js` (`DU_CONFIG`: названия поэтажных планов, ряд планов и цвета зон ДУ — настройки под проект). Их человекочитаемые копии — `docs/`.
- `src/icons/plan/` — значки «Норма» для планов (по `PLAN_ICONS`: DriverUID → файл; подбор по названию драйвера; без записи — синяя точка; живых состояний нет). `src/icons/tree/` — значки дерева: `NN.png`, `drv-*.png` (драйверы без записи в `PLAN_ICONS`: ЗП, АЛС, Линия БМП, группы индикаторов/реле, Локальная сеть — через `TREE_DRV_ICONS` в `js/trees.js`, ключи в `tree-icons.js`; на планах остаётся синяя точка), `t-zone|delay|plan|folder.png` (зоны, сценарии, планы, папка планов; подбор по `t-<item.k>.png` в шаблоне `TreeNode`, `js/ui.js`).
- `data/` (вне репозитория, локально) — образцы архивов, журналов, сборок ГК и документации.

## Просмотрщик

Запуск: открыть `src/index.html` (работает и через `file://`), перетащить `.fscp` в рамку. Отладка: `?sample=<url архива>`, `?log=<url csv>`; при `?sample=` восстановление состояния отключено.

### Архитектура

- Модули `src/js/` — обычные скрипты, **не ES-модули** (иначе не работает `file://`); общая глобальная область, имена верхнего уровня уникальны во всех файлах; `import`/`export` не вводить. Порядок в `index.html` важен только для `util.js` (деструктуризация `Vue`, первым) и `app.js` (`App`, регистрация компонентов, запуск, последним).
- Поток данных: `archive.js` (загрузка zip) → `files.js` (sniff, GUID-индекс `guidIndex`, `refs`) → `model.js` (`buildModel`, XML-хелперы `child/txt/subs`) → `trees.js` (`TREES`, подписи, детали) → `ui.js` и `views-*.js` (отрисовка). Остальное: `util` (fmt/clip), `state` (реактивное состояние, `go`, `ask`, `S` — zip и кэши), `idb`, `log` (CSV, `readLogs`, `logLink`), `parameters` (сравнение параметров), `welcome`, `settings`.
- Vue 3 (глобальная сборка с компилятором, шаблоны — строками в `js/`). Тяжёлое (zip, DOM XML, тексты) — вне реактивности (`shallowRef`/переменные). Архив читается в браузере через JSZip, на сервер ничего не уходит. GUID ссылок ищутся индексом (один проход регуляркой на файл), адреса устройств кэшируются (`addrCache`), XML парсится `DOMParser`, дерево строится лениво; для `Content/<guid>` тип — по сигнатуре (`sniff`), GUID ищется `indexOf` по всем XML.
- Навигация — `go({type, ...})`; каждый переход пересоздаёт компонент. После загрузки открывается дерево устройств. Вкладки (`TABS`, `app.js`): Устройства, Зоны, Сценарии, Зоны ДУ, Логика, Логика БМП, Планы; плюс «Сырые данные», журнал, настройки.
- Хранение: открытый архив и журнал — IndexedDB `fscp-viewer` (ключи: `file` — архив, `log` — журнал, `plans` — правки планов; их сигнатура — имя, размер и дата изменения архива, `planSig`); текущая вкладка — `localStorage.fscpTab`; настройки интерфейса — `fscp.theme`, `fscp.icons`, `fscp.nav`, `fscp.det`, `fscp.du`, `fscp.planSim`, `fscp.planEdit`, `fscp.planCenter`, `fscp.planW`, `fscp.l3*`. Все ключи с префиксом `fscp` чистит «Удалить данные» в настройках (с подтверждением; также чистит IndexedDB и перезагружает).
- Компоненты: `WelcomeView` (стартовая рамка; несколько архивов — загружается первый, с уведомлением), `LogInfoView`, `PlanCanvas` (`plan-canvas.js`; области зон ДУ — `duBuildPaths` в `du-paths.js`; дерево и панель деталей — `TreeView` в `views-tree.js`), `RawView`, `FileView`, `XmlView`, `SourceView` (виртуальная прокрутка), `TreeView` + `TreeNode` (раскрытые узлы — `Set` путей), `LogicNode`, `LogicView`, `BmpLogicView`, `DetailTable`, `LogView`, `SettingsView` (тема). Модальное окно одно, в `App`: `ask({ title, text, items, note, ok, cancel, danger })` → `Promise<boolean>`.

### Деревья

Устройства / Зоны / Сценарии / Планы описаны в `TREES`, элементы — `devItem`/`zoneItem`/`delayItem`/`planItem`. Панель деталей, хлебные крошки, поиск или фильтр по подписи/UID, бейджи (подписи/количества), ссылки «файл:строка» и переходы между деревьями.

- Клавиатура (когда `#tview` в фокусе; клик по узлу фокусирует): ↑↓, ←→ (свернуть/раскрыть/к родителю), Home/End, PgUp/PgDn, Enter/Space. Реестр узлов — `st.reg` (заполняет `TreeNode`), обработчик — `onKey`.
- Устройства: в рамке — `[полный адрес] PredefinedName || имя драйвера`, затем `Description`. `DRIVERS`: `DriverUID → [имя, описание, иконка, без адреса, есть дети, категория]`; неизвестные GUID считаются в шапке.
- Параметры сравниваются с `DEVICE_DEFAULTS` (`js/parameters.js`): сопоставление по GUID драйвера и точному `Name`, одинаковые копии из `Properties`/`DeviceProperties` объединяются, неизвестные эталоны не считаются совпадением. В дереве — `≠ N`, в деталях — таблица с подсветкой. Блок «Параметры» (все значения) — у любого устройства с параметрами; «Сравнение параметров» — только если есть что показать (отличия, нет эталона драйвера, несравнённые). Это дефолты версии ПО, не гарантия заводских настроек.
- Зоны — `Zones/GKZone`; потомки — устройства с этой зоной в `ZoneUIDs`. Сценарии — `Delays/GKDelay`; потомки — устройства из `DirectionDevices/DirectionDevice`.
- Планы — `Plans/Plan` по `Children/Plan`. На холсте элементы сортируются по `ZLayer` (сценарии 11, зоны 60, устройства 70), затем по `ZIndex`; точки — всегда сверху.

### Производительность холста

`hit()` ищет по пространственной сетке (`grid`, ячейка 80; сбрасывается при любом изменении `objs`), цвета сетки кэшируются по теме (`gridColors`), размер значка считается по ячейкам, имитация (`relit`) — обход в ширину по `out`-связям графа. Число устройств с отличиями параметров (`diffCount`) считается порциями в простое (`idle`).

### Редактор планов (`PlanCanvas`, кнопка с карандашом)

Правки пишутся прямо в XML-узлы `PlansConfiguration.xml` (`o.el`): перенос, ручки размера и вершин, новая вершина (двойной клик по ребру), удаление вершины (Alt+клик), удаление элемента (Del), добавление устройства/зоны/сценария клоном существующего элемента, undo/redo (Ctrl+Z / Ctrl+Y). Состояние сохраняется в IndexedDB (`plans`, с паузой 2 с и в простое) и подменяет `PlansConfiguration.xml` при следующей загрузке того же архива; «Скачать .fscp» собирает архив с изменёнными планами, «Сбросить» чистит правки и перезагружает страницу. При закрытии архива правки удаляются.

### Логика сценариев (`views-logic.js`)

Вкладка «Логика» (`LogicView`) — схема на SVG, строится автоматически.
- `buildGraph` (кэш `model.graph`): граф «устройства из условий → зоны → сценарии (слои по глубине цепочек «сценарий → сценарий») → исполнители (`DirectionDevices`)» из `Logic/GKClause` (`DeviceUIDs`/`ZoneUIDs`/`DelayUIDs`) и `devByZone`. `Fire1Count` сохраняется в узле зоны (`f1`), `ClauseOperationType` и тип условия не учитываются.
- `buildLogicGroups` (кэш `model.lgroups`): схлопывает узлы в группы по шаблону имени (числа → №, устройства — по имени драйвера); порядок внутри слоя — по среднему положению связей. Исполнители `ШУН-В` и `МДУ*` делятся на `… ДП|ДВ|ОЗК`, `МВК` — на `стробы|шторы` (признак из `Description` устройства, иначе из имени сценария, где оно исполнитель).
- Управление: колёсико — зум к курсору, перетаскивание — сдвиг. Блок — «плашка» (цвет типа, справа за разделителем число объектов группы); клик по секции с числом раскрывает состав группы мини-блоками в том же столбце (нижние сдвигаются, выезд по одному, >40 — «… и ещё N»), клик по мини-блоку — в дерево. Подсказок над схемой и отступов вокруг холста нет.
- Наведение на блок подсвечивает путь вверх и вниз; клик оставляет только блоки этого пути, выстраивает их заново с анимацией (400 мс, `animate`/`scene`) и показывает состав блока чипами-ссылками (переход в дерево); повторный клик по блоку или пустому месту возвращает всё.
- «Логика БМП» (`BmpLogicView`, `openBmp` в `archive.js`): дерево БМП/БМП2 (`BMP_DRIVERS`), справа — укрупнённый `PlanCanvas` с устройствами под выбранным БМП.

### Зоны ДУ (дымоудаление)

Схема именования сценариев — в `docs/FSCP.md`, §2. Вкладка «Зоны ДУ» (`m.duList`, `m.duOf`: UID устройства → номера зон, `m.duPlans`): дерево зона → сценарии → устройства; справа один холст со всеми поэтажными планами друг под другом (подвал сверху, 3 этаж снизу; `PlanCanvas` с `plans`, подложки — `segs` со смещением по Y; общий зум и панорама, двойной клик — вписать; кнопок этажей нет).
- Области зон строятся из фигур (полигонов/прямоугольников) пожарных зон:
  - фигуры зон из условия (`Logic/ZoneUIDs`) сценария `Зона ДУ N ПОЖАР` (`m.duZones`: UID зоны → номера зон ДУ; зона в нескольких — «общая» оранжевая). Фигуры зон лежат на одних планах, а устройства ДУ — на одноимённых с той же подложкой, поэтому `collect` подтягивает фигуры с одноимённых планов (`ov`).
- Отрисовка: на каждую зону один `Path2D` (`duBuild`), заливка `nonzero` в режиме `multiply`, подсказка — `isPointInPath` (`duAt`); растров и чтения пикселей нет. При выбранной зоне видны только её область (+ «общая») и её МДУ (значки `PLAN_ICONS`, без кружков и цифр), вокруг области — пурпурная рамка с белой подложкой; без выбора — все. Подсказка при наведении — «Зона ДУ N» (для «общей» — список номеров). На вкладке «Планы» то же включается кнопкой «ДУ».
- Кнопка «Имитация» (▶, `fscp.planSim`): клик по устройству/зоне/сценарию на плане переключает «сработку» (красный значок/заливка); цепочка — по графу `buildGraph` (узел срабатывает, если сработал любой вход), сброс — выключением режима.

### Журнал (`LogView`)

CSV из ГК грузится вместе с `.fscp` (можно несколько файлов, дубли по `UID` отбрасываются). Связь с конфигом и разбор полей — `docs/FSCP.md`, §5; расшифровки `Name`/`Description` — `EVENTS`/`EVENT_DESCS` (`docs/EVENTS.md`). В деталях объекта строка «События» открывает лог с фильтром (`logLink`; у зоны — ещё события её устройств). Цветная точка по важности — `evSev`.

### Стиль

Контролы (`button`, `input[type=search]`, `select`) высотой `--ctl` (32px), скругление 8px, акцентное кольцо фокуса. Полосы прокрутки — `::-webkit-scrollbar` 16px (`scrollbar-width`/`scrollbar-color` ломают webkit-ширину — только запасной вариант для Firefox). Edge с Fluent-полосами игнорирует стили сайта: отключить в `edge://settings/appearance`.
